# Generation UIs: result contract for media tiles

Sibling to `adapters.md`. That file covers LLM chats where the result is an
assistant text node. Generation UIs (Flow, image/video tools) return MEDIA
TILES, and the completion contract is different in four ways that break chat-shaped
code.

## The four differences

| Concern | LLM chat | Generation UI |
|---|---|---|
| Result identity | last message node, text hash | NEW tile id absent from a pre-submit snapshot |
| Virtualization | old nodes leave DOM | only a rendered WINDOW of tiles exists; raw counts mislead |
| Fetch bytes | none needed | must pull real bytes (signed URLs, size variants) |
| Label source | message text | per-tile footer label, used as the search key for later refs |

## Result detection

Snapshot the tile id list BEFORE submit; poll until an id not in the snapshot
appears. A raw tile query sees only the rendered window, so a census that trusts
it under-reports — enumerate by scrolling the virtual scroller, or search the
picker by name instead. Never infer "generated" from a count going up.

## Reference attachment: two distinct scopes

Chip counting and asset search have different DOM roots. Using one for both is
the top cause of attach failures.

- **Picker scope** — the search input and result rows live under the popover
  custom element. Query the popover root, normalize away the trailing
  "Imagen"/"Image" suffix on labels, match on the name without its extension.
- **Composer scope** — walk UP from the lowest visible editor to the ancestor
  containing the submit button, and count chips there. Batch-history chips use
  the same tag name elsewhere in the DOM; an unscoped count reports ghosts and
  every diff assertion breaks.

Assert an EXACT per-reference chip delta. A step that reports "attached" on a
non-1 diff will silently build a scene with missing references, and the model
will drift off-style without any error surfacing.

Type into search boxes with the native `value` setter plus an `input` event
(frameworks ignore execCommand). If clicking a row does not add a chip, a
separate confirm control is the second step — clicking the row alone may only
select it. Normalize labels, not filenames, when attaching tiles generated by an
earlier run.

## Fetching the bytes

Fetch page-side from the tile's `img.src`; a signed URL downloaded from outside
the page can fail on origin or size binding. Try a size-variant upscale first,
then fall back to the original URL — the fallback is mandatory, not defensive
noise, because the variant can reject while the original succeeds. Base64 the
buffer in chunks; one `String.fromCharCode.apply` over a large buffer overflows
the stack.

## Uploads are usually gesture-locked

File upload in these UIs commonly ignores synthetic clicks, trusted CDP mouse,
file-chooser events, and clipboard image paste. Do not spend attempts on it.
Check whether the asset is ALREADY present in the picker before concluding it is
missing; if truly absent, the user drags it in and the attach is retried after.

## Parametrize from the first script

Project id, prompt, refs, output dir, filename, and both state paths belong in
env vars from the start. Single-shot scripts get reused across projects within
days; hardcoded paths force a rewrite. Keep the pre-submit snapshot and the
post-poll result in SEPARATE files — sharing one path lets the poll read its own
output and mis-attribute the new tile.
