# MILO_PERFORMANCE_LEARNING_LOOP (third component)

Hermes learns from MILO's own videos, not from a generic definition of viral. DESIGN_MASTER builds, SUCCESS_ENGINE selects, this loop calibrates.

## 1. MILO_PERFORMANCE_MEMORY (per published episode, appended to `story_evidence.md`)

guion + hook + imágenes + ritmo + duración + tema + estructura narrativa + hora + plataforma + views + retención 3 s + retención 5 s + watch time + completion + shares + comments + distribución.

No partial rows: a published episode without metrics is an open loop — chase the numbers before the next selection.

## 2. Pattern mining (Hermes, with tools, after every ≥3 new data points)

Compare predicted (scores, survival rows) vs real (retention, completion, shares). Record patterns ONLY as cited regularities, e.g. "visual-danger hooks retain better than explanatory intros (R009–R012, +x%)", "first visual change after 2.5 s loses viewers", "twist X works only with setup before second 12". One counterexample pauses the pattern; two kill it.

## 3. Champion update

The Champion is the best-evidenced historical pattern, not the highest-scored script. A Challenger dethrones it only with real metrics beating it on defined criteria, never with a higher LLM score. Experimental hypotheses (one variable each) are the only other production path — and their results feed back here.

## 4. Criteria updates

When patterns harden, update SUCCESS_ENGINE criteria (weights, survival questions, Opening Lab minima) with a dated entry citing the episodes. When 90–100-scored stories stop beating 80–89 ones, declare the evaluator miscalibrated and fix it — never silently keep scoring.

## 5. Orchestration

Hermes runs all three components end-to-end, including multi-LLM AUTO-RECOVERY on any step failure. Human only for the truly unresolvable or external info/credentials/decisions.
